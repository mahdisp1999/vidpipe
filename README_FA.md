# راهنمای vidpipe

برنامهٔ `vidpipe` یک ابزار ویدئوی محلی با دو حالت است:

- **بهبود کیفیت (Enhancement):** ویدئو را با FFmpeg به فریم‌های تصویری تبدیل می‌کند، فریم‌ها را به‌ترتیب از زنجیره‌ای از مدل‌ها عبور می‌دهد و نتیجه را دوباره Encode می‌کند. فریم‌ها در صف‌های محدود حافظهٔ RAM جابه‌جا می‌شوند و برای هر فریم فایل موقت جداگانه ساخته نمی‌شود.
- **حذف بازه‌ها بدون افت کیفیت (Lossless):** یک یا چند بازهٔ زمانی را با Stream Copy در FFmpeg (`-c copy`) از ویدئو حذف می‌کند. هیچ چیزی دوباره Encode نمی‌شود.

موتور فعلی اجرای مدل **PyTorch + Spandrel** است. در این نسخه ONNX و TensorRT پیاده‌سازی نشده‌اند. هیچ وابستگی جدیدی به `requirements.txt` اضافه نشده است.

## امکانات

- حذف بازه‌های زمانی (`--remove-range`) بدون Re-encode، با سه Backend خودکار: pipe، tmpfs و disk.
- گزارش زنده و تک‌خطی در CLI؛ هر بار همان خط بازنویسی می‌شود و درصد پیشرفت، تعداد فریم‌ها، فریم‌های باقی‌مانده، FPS، زمان سپری‌شده و ETA را نشان می‌دهد.
- رنگی و Bold شدن اطلاعات مهم در ترمینال تعاملی.
- کنترل فوری با کیبورد: `P` برای مکث، `R` برای ادامه و `S` یا `Q` برای توقف؛ نیازی به Enter نیست. در لینوکس برنامه در صورت Redirect بودن stdin از ترمینال کنترل‌کننده (`/dev/tty`) استفاده می‌کند.
- تبدیل `Ctrl+C` به درخواست توقف کنترل‌شده، به‌جای قطع ناگهانی Threadها.
- پردازش دسته‌ای کاشی‌ها (Tile Batching) و بازیابی پس از خطای کمبود حافظهٔ CUDA.
- Threadهای جداگانه برای خواندن، پردازش و نوشتن ویدئو با صف‌های محدود.
- اندازه‌گیری زمان هر مرحله، وضعیت صف‌ها و اطلاعات حافظهٔ VRAM از PyTorch.
- نام خروجی شامل زنجیرهٔ مدل‌ها، ضریب Scale نهایی و برچسب Denoise در صورت نیاز.
- دستور مستقیم `vidpipe` همراه با راهنمای کامل `--help` و گزینه‌های مشاهدهٔ قابلیت‌های FFmpeg.

## پیش‌نیازها

- Python نسخهٔ 3.10 یا جدیدتر (نسخهٔ 3.12 پیشنهاد می‌شود).
- نصب بودن FFmpeg و FFprobe و در دسترس بودن آن‌ها از طریق `PATH`.
- برای بهبود کیفیت: PyTorch، Spandrel و NumPy.
- برای خواندن تنظیمات: PyYAML.
- برای اجرای GPU: درایور NVIDIA و نسخهٔ CUDA-enabled از PyTorch. اجرای CPU نیز پشتیبانی می‌شود.
- برای حذف بازه‌ها فقط FFmpeg و FFprobe لازم است.

نصب FFmpeg در Ubuntu، در صورت نیاز:

```
sudo apt install ffmpeg
```

## نصب

یک محیط مجازی بساز و فعال کن، سپس وابستگی‌های پروژه را نصب کن. نسخهٔ PyTorch متناسب با CUDA یا CPU سیستم را جداگانه نصب کن.

با `uv`:

```
uv venv --python 3.12
source .venv/bin/activate
uv pip install -r requirements.txt
```

با `pip`:

```
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

نصب فرمان CLI:

```
./scripts/install-cli.sh
```

این اسکریپت یک Symlink در `~/.local/bin/vidpipe` می‌سازد که به همین نسخهٔ مخزن اشاره می‌کند. مطمئن شو `~/.local/bin` در `PATH` قرار دارد و پیش از اجرای برنامه همان محیط مجازی را فعال کرده‌ای.

```
vidpipe --help
vidpipe --version
```

## اجرای سریع

بهبود کیفیت: فایل وزن مدل‌ها را داخل پوشهٔ `models/` قرار بده (این پوشه در Git ذخیره نمی‌شود)، مسیر هر `model:` را در `config.yaml` تنظیم کن و سپس اجرا کن:

```
vidpipe input.mp4
```

اگر `--output` مشخص نشده باشد، فایل خروجی داخل `output/` و با نامی ساخته می‌شود که زنجیرهٔ پردازش را نشان می‌دهد:

```
input__1xDeJPG_OmniSR__then__realesr-general-wdn-x4v3__scale-4x__denoised.mkv
```

حذف بازه‌ها (نیازی به مدل یا `config.yaml` نیست):

```
vidpipe input.mkv --remove-range 00:10:00-00:15:00
```

## کنترل کیبورد هنگام پردازش

در حالت بهبود کیفیت، اگر ورودی استاندارد به یک ترمینال تعاملی متصل باشد، کلیدها بلافاصله دریافت می‌شوند:

| کلید     | عملکرد                 |
|----------|------------------------|
| `P`      | مکث پردازش             |
| `R`      | ادامهٔ پردازش          |
| `S`      | درخواست توقف کنترل‌شده |
| `Q`      | درخواست توقف کنترل‌شده |
| `Ctrl+C` | درخواست توقف کنترل‌شده |

بعد از فشردن کلیدهای کنترلی Enter نزن. هنگام اجرای کار، ترمینال موقتاً در حالت دریافت کاراکتر به‌صورت مستقیم قرار می‌گیرد و پس از پایان پردازش تنظیمات قبلی آن بازگردانده می‌شود.

اگر ورودی استاندارد Redirect شده یا از Pipe دریافت شود، کنترل تک‌کلیدی در دسترس نیست. در صورت اتصال فرایند به ترمینال، `Ctrl+C` همچنان قابل استفاده است.

## نمایش پیشرفت

در حالت بهبود کیفیت، بعد از یک هدر کوتاه (ورودی، خروجی، رزولوشن، مدل‌ها، دستگاه و دقت)، برنامه یک **پنل زنده‌ی شش‌خطی** نشان می‌دهد. این پنل در همان محل ترمینال بازنویسی می‌شود: مکان‌نما به‌اندازه‌ی ارتفاع پنل به بالا برمی‌گردد (`ESC[nA`) و هر خط قبل از نوشتن پاک می‌شود (`ESC[2K`)، پس ترمینال پایین‌رو اسکرول نمی‌شود.

نمونهٔ تصویری (اعداد فرضی‌اند):

```
RUNNING    [██████████░░░░░░░░░░░░░░░░░░░░]  31.50% done   68.50% left
Frames     315 / 1,000                Remaining  685 frames
Speed      0.35 fps                   Elapsed    00:15:00    ETA 00:32:37
Model      realesr-general-x4v3       Tiles      4 / 12 @192px b2
Queue      in 2/4  out 1/4            VRAM       5.42 / 8.00 GB
GPU        96%
Per frame  decode 8 ms | process 2700 ms | encode 12 ms
```

نکات:

- درصد انجام‌شده و باقی‌مانده از یک شمارش فریم محاسبه می‌شوند، پس همیشه جمعشان ۱۰۰٪ است.
- وقتی شمارش فریم تخمینی است (مثلاً برای ویدئوی با نرخ فریم متغیر)، کنار عدد `~` و عبارت `(approx.)` نمایش داده می‌شود.
- `Elapsed` زمان دیواری از شروع اجراست و زمان مکث را هم شامل می‌شود. `ETA` بر پایه‌ی سرعت هموارشده محاسبه می‌شود.
- فیلد `GPU` به پکیج `pynvml` نیاز دارد (در `requirements.txt` آمده است). اگر نصب نباشد، `n/a` نمایش داده می‌شود.
- فیلد `OOM` فقط وقتی ظاهر می‌شود که بازیابی حافظهٔ CUDA اجرا شده باشد.
- وقتی خروجی به فایل یا Pipe هدایت شود، هر به‌روزرسانی یک خط است که بخش‌هایش با `|` از هم جدا شده‌اند.

گزینه‌های گزارش پیشرفت:

```
--progress-interval SECONDS   فاصله‌ی زمانی به‌روزرسانی (پیش‌فرض: 1.0)
--no-progress                 غیرفعال‌کردن پنل زنده (هدر همچنان چاپ می‌شود)
--no-color                    غیرفعال‌کردن رنگ‌های ANSI
```

حذف بازه‌ها خطوط وضعیت کوتاه خودش را چاپ می‌کند و از این پنل استفاده نمی‌کند.

## مرجع دستورات

نمایش تمام گزینه‌ها:

```
vidpipe --help
```

### ورودی و خروجی

```
vidpipe INPUT
vidpipe INPUT --output ./output/enhanced.mp4
vidpipe INPUT --output-dir ./output
vidpipe INPUT --config ./config.yaml
vidpipe INPUT --overwrite
```

- `INPUT`: فایل ویدئوی ورودی؛ FFmpeg معمولاً فرمت آن را خودکار تشخیص می‌دهد.
- `-o, --output`: مسیر دقیق فایل خروجی.
- `--output-dir`: پوشهٔ نام‌های خروجی خودکار (فقط در حالت بهبود کیفیت).
- `--config`: فایل تنظیمات YAML.
- `--overwrite`: اجازهٔ جایگزینی فایل خروجی موجود.

### حذف بازه‌های زمانی

```
vidpipe INPUT --remove-range START-END [--remove-range START-END ...] [-o OUTPUT] [--overwrite]
```

```
vidpipe lecture.mkv --remove-range 00:10:00-00:15:00
vidpipe lecture.mkv --remove-range 90-120 --remove-range 1:02:00-1:02:30 -o lecture_trimmed.mkv
```

- هر بازه به شکل `START-END` نوشته می‌شود. هر طرف می‌تواند ثانیه (`90`)، `MM:SS` (`1:30`) یا `HH:MM:SS.fraction` (`00:01:30.5`) باشد.
- بازه‌ها باید داخل طول ویدئو باشند. بازه‌های هم‌پوشان ادغام می‌شوند. حذف کل ویدئو خطا است.
- خروجی پیش‌فرض `<نام>_cut<پسوند>` کنار فایل ورودی است. در این حالت `--output-dir` استفاده نمی‌شود.
- ویدئو و صدا بدون Encode دوباره کپی می‌شوند. نقطهٔ برش روی Keyframe می‌نشیند، پس ممکن است چند دهم ثانیه با زمان دقیق فاصله داشته باشد. فاصلهٔ Keyframeها (GOP) حد این خطاست: اگر ویدئو هر ۱۰ ثانیه یک Keyframe داشته باشد، برش تا حدود ۱۰ ثانیه جابه‌جا می‌شود.
- vidpipe سه Backend را به‌ترتیب امتحان می‌کند: `pipe` (یک پاس FFmpeg و بدون فایل موقت)، بعد `tmpfs` (بخش‌های موقت در `/dev/shm`) و بعد `disk`. اولین روشی که کار کند استفاده می‌شود و نام آن چاپ می‌شود.
- فایل‌های موقت بعد از موفقیت یا شکست پاک می‌شوند. خروجی با نام موقت نوشته می‌شود و فقط وقتی کامل شد با نام نهایی جایگزین می‌شود.
- حذف بازه‌ها فایل `config.yaml` را نمی‌خواند، مدل لود نمی‌کند و دستگاه انتخاب نمی‌کند.

### تنظیمات Encode

```
vidpipe INPUT --codec libx264 --crf 18 --preset slow
vidpipe INPUT --codec libx265 --crf 22 --preset medium
vidpipe INPUT --codec h264_nvenc --no-crf --video-option rc=vbr --video-option cq=19
vidpipe INPUT --pixel-format yuv420p --audio-codec aac --format mp4
```

| گزینه                        | کاربرد                                                                     |
|------------------------------|----------------------------------------------------------------------------|
| `--codec` یا `--video-codec` | انکودر ویدئو در FFmpeg؛ مانند `libx264`، `libx265` یا `h264_nvenc`         |
| `--crf N`                    | مقدار کیفیت برای انکودرهای پشتیبان CRF؛ محدودهٔ معتبر به انکودر بستگی دارد |
| `--no-crf`                   | ارسال نکردن گزینهٔ `-crf`؛ برای انکودرهایی که کنترل کیفیت دیگری دارند      |
| `--preset NAME`              | Preset سرعت/کیفیت؛ مقادیر معتبر به انکودر انتخاب‌شده وابسته‌اند            |
| `--pixel-format FORMAT`      | فرمت پیکسل خروجی؛ مانند `yuv420p`، `yuv444p` یا `p010le`                   |
| `--audio-codec NAME`         | انکودر صدا یا `copy`؛ مقدار `none` صدا را حذف می‌کند                       |
| `--format NAME`              | Container/Muxer خروجی؛ مانند `matroska`، `mp4` یا `webm`                   |
| `--video-option KEY=VALUE`   | گزینهٔ اضافی انکودر ویدئو؛ برای چند گزینه می‌توان آن را تکرار کرد          |

این گزینه‌ها فقط برای بهبود کیفیت هستند. `CRF` برای همهٔ انکودرها قابل استفاده نیست؛ برای نمونه NVENC معمولاً از `cq` یا `rc` استفاده می‌کند. گزینه‌های معتبر را در مستندات FFmpeg همان انکودر بررسی کن.

### تنظیمات Decode

```
vidpipe INPUT --input-format mov --decoder h264
```

| گزینه                 | کاربرد                                                              |
|-----------------------|---------------------------------------------------------------------|
| `--input-format NAME` | اجبار FFmpeg به استفاده از Demuxer مشخص؛ حالت عادی تشخیص خودکار است |
| `--decoder NAME`      | اجبار به استفاده از Decoder مشخص؛ حالت عادی انتخاب خودکار است       |

### پردازش و حافظه

```
vidpipe INPUT --device gpu --tile-size 192 --tile-pad 16 --batch-size 2
vidpipe INPUT --device cpu --queue-depth 2 --no-half
```

| گزینه                     | کاربرد                                          |
|---------------------------|-------------------------------------------------|
| `--device {auto,gpu,cpu}` | انتخاب دستگاه اجرای مدل                         |
| `--tile-size N`           | عرض و ارتفاع کاشی برحسب پیکسل؛ حداقل ۶۴         |
| `--tile-pad N`            | حاشیهٔ همسایگی اطراف هر کاشی                    |
| `--batch-size N`          | تعداد کاشی‌های هم‌اندازه در هر فراخوانی مدل     |
| `--queue-depth N`         | حداکثر تعداد فریم نگهداری‌شده در هر صف Pipeline |
| `--half`                  | درخواست FP16 در صورت پشتیبانی مدل CUDA          |
| `--no-half`               | اجبار به اجرای مدل با FP32                      |

Batch بزرگ‌تر ممکن است سرعت را افزایش دهد، اما VRAM بیشتری مصرف می‌کند. اگر خطای CUDA Out of Memory رخ دهد، مرحلهٔ مدل ابتدا Batch Size و سپس Tile Size را کاهش می‌دهد و فریم جاری را دوباره امتحان می‌کند.

### مشاهدهٔ قابلیت‌های FFmpeg

```
vidpipe --list-encoders
vidpipe --list-decoders
vidpipe --list-formats
vidpipe --list-pixel-formats
```

این دستورات انکودرها، دیکودرها، Demuxer و Muxerها و Pixel Formatهای موجود در FFmpeg نصب‌شده را نشان می‌دهند.

## تنظیمات

فایل `config.yaml` شامل مراحل پردازش، دستگاه اجرا، محدودیت‌های حافظه، عمق صف‌ها و تنظیمات Encode است. مراحل داخل `stages` به همان ترتیبی اجرا می‌شوند که در فایل نوشته شده‌اند. حذف بازه‌ها این فایل را نادیده می‌گیرد.

نمونهٔ کلی یک مرحلهٔ مدل:

```
stages:
  - name: model
    model: models/your-model.pth
    tile_size: 192
    tile_pad: 16
    batch_size: 1
    batch_size_max: 4
    half: true
```

برای انتخاب Tile Size، Padding و دقت محاسباتی، مستندات خود مدل را بررسی کن. همهٔ مدل‌ها از FP16 یا تمام اندازه‌های کاشی پشتیبانی نمی‌کنند.

## نام‌گذاری خروجی

در بهبود کیفیت، اگر `--output` تعیین نشده باشد، `naming.py` نام فایل را از نام ورودی، نام مدل‌ها به ترتیب اجرا، ضریب Scale ترکیبی و برچسب Denoise (در صورت تشخیص از نام مدل) می‌سازد.

در حذف بازه‌ها، بدون `--output` نام خروجی `<نام>_cut<پسوند>` کنار ورودی است. در هر دو حالت، `--output` نام خودکار را کنار می‌گذارد.

## اجرای تست‌ها

از ریشهٔ مخزن اجرا کن:

```
python -m pytest -q
```

تست‌ها اعتبارسنجی تنظیمات، وضعیت Controller، دریافت کلید بدون Enter، مدیریت حافظه، پردازش کاشی و بازیابی OOM، نام‌گذاری خروجی، Pipeline، گزارش پیشرفت، اطلاعات ویدئو و حذف بازه‌ها (`test_cut.py`) را بررسی می‌کنند. تست‌های حذف بازه‌ها FFmpeg واقعی را روی یک کلیپ ساختگی اجرا می‌کنند، بررسی می‌کنند فریم‌های Decode شده با منبع یکسان باشند (یعنی Re-encode نشده) و مطمئن می‌شوند فایل موقتی باقی نمی‌ماند. اگر FFmpeg نصب نباشد این تست‌ها رد می‌شوند.
