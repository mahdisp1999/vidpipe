# راهنمای vidpipe

برنامه `vidpipe` یک خط لولهٔ محلی برای افزایش کیفیت ویدئو است. برنامه با FFmpeg ویدئو را به فریم‌های تصویری تبدیل می‌کند، فریم‌ها را به‌ترتیب از زنجیره‌ای از مدل‌ها و مراحل پردازش عبور می‌دهد و در پایان ویدئوی خروجی را Encode می‌کند. فریم‌ها در صف‌های محدود حافظهٔ RAM جابه‌جا می‌شوند و برای هر فریم فایل موقت جداگانه ساخته نمی‌شود.

موتور فعلی اجرای مدل **PyTorch + Spandrel** است. در این نسخه ONNX و TensorRT پیاده‌سازی نشده‌اند. هیچ وابستگی جدیدی به `requirements.txt` اضافه نشده است.

## امکانات

- گزارش زنده و تک‌خطی در CLI؛ هر بار همان خط بازنویسی می‌شود و درصد پیشرفت، تعداد فریم‌ها، فریم‌های باقی‌مانده، FPS، زمان سپری‌شده و ETA را نشان می‌دهد.
- رنگی و Bold شدن اطلاعات مهم در ترمینال تعاملی.
- کنترل فوری با کیبورد: `P` برای مکث، `R` برای ادامه و `S` یا `Q` برای توقف؛ نیازی به Enter نیست. در لینوکس برنامه در صورت Redirect بودن stdin از ترمینال کنترل‌کننده (`/dev/tty`) استفاده می‌کند.
- تبدیل `Ctrl+C` به درخواست توقف کنترل‌شده، به‌جای قطع ناگهانی Threadها.
- پردازش دسته‌ای کاشی‌ها و بازیابی پس از خطای کمبود حافظهٔ CUDA.
- Threadهای جداگانه برای خواندن، پردازش و نوشتن ویدئو با صف‌های محدود.
- اندازه‌گیری زمان هر مرحله، وضعیت صف‌ها و اطلاعات حافظهٔ VRAM از PyTorch.
- نام خروجی شامل زنجیرهٔ مدل‌ها، ضریب Scale نهایی و برچسب Denoise در صورت نیاز.
- دستور مستقیم `vidpipe` همراه با راهنمای کامل `--help` و گزینه‌های مشاهدهٔ قابلیت‌های FFmpeg.

## پیش‌نیازها

- Python نسخهٔ 3.10 یا جدیدتر (نسخهٔ 3.12 پیشنهاد می‌شود).
- نصب بودن FFmpeg و FFprobe و در دسترس بودن آن‌ها از طریق `PATH`.
- برای اجرای مدل: PyTorch، Spandrel و NumPy.
- برای خواندن تنظیمات: PyYAML.
- برای اجرای GPU: درایور NVIDIA و نسخهٔ CUDA-enabled از PyTorch. اجرای CPU نیز پشتیبانی می‌شود.

نصب FFmpeg در Ubuntu، در صورت نیاز:

```bash
sudo apt install ffmpeg
```

## نصب

یک محیط مجازی بساز و فعال کن، سپس وابستگی‌های موجود پروژه را نصب کن. نسخهٔ PyTorch متناسب با CUDA یا CPU سیستم را جداگانه نصب کن.

با `uv`:

```bash
uv venv --python 3.12
source .venv/bin/activate
uv pip install -r requirements.txt
```

با `pip`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

نصب فرمان CLI:

```bash
./scripts/install-cli.sh
```

این اسکریپت یک Symlink در `~/.local/bin/vidpipe` می‌سازد که به همین نسخهٔ مخزن اشاره می‌کند. مطمئن شو `~/.local/bin` در `PATH` قرار دارد و پیش از اجرای برنامه همان محیط مجازی را فعال کرده‌ای.

```bash
vidpipe --help
vidpipe --version
```

## اجرای سریع

فایل وزن مدل‌ها را داخل پوشهٔ `models/` قرار بده (این پوشه در Git ذخیره نمی‌شود)، سپس مسیر فایل مدل را در `config.yaml` تنظیم کن.

```bash
vidpipe input.mp4
```

اگر `--output` مشخص نشده باشد، فایل خروجی داخل `output/` و با نامی ساخته می‌شود که زنجیرهٔ پردازش را نشان می‌دهد. برای نمونه:

```text
input__1xDeJPG_OmniSR__then__realesr-general-wdn-x4v3__scale-4x__denoised.mkv
```

برای تعیین دقیق نام و مسیر خروجی از `--output` استفاده کن.

## کنترل کیبورد هنگام پردازش

اگر ورودی استاندارد برنامه به یک ترمینال تعاملی متصل باشد، کلیدها بلافاصله دریافت می‌شوند:

| کلید | عملکرد |
|---|---|
| `P` | مکث پردازش |
| `R` | ادامهٔ پردازش |
| `S` | درخواست توقف کنترل‌شده |
| `Q` | درخواست توقف کنترل‌شده |
| `Ctrl+C` | درخواست توقف کنترل‌شده |

بعد از فشردن کلیدهای کنترلی Enter نزن. هنگام اجرای کار، ترمینال موقتاً در حالت دریافت کاراکتر به‌صورت مستقیم قرار می‌گیرد و پس از پایان پردازش تنظیمات قبلی آن بازگردانده می‌شود.

اگر ورودی استاندارد Redirect شده یا از Pipe دریافت شود، کنترل تک‌کلیدی در دسترس نیست. در صورت اتصال فرایند به ترمینال، `Ctrl+C` همچنان قابل استفاده است.

## نمایش پیشرفت

گزارش پیشرفت در ترمینال به‌صورت یک **پنل ثابت دوخطی** نمایش داده می‌شود. با استفاده از Carriage Return (`\r`)، حرکت مکان‌نما به خط بالاتر و کد پاک‌کردن ادامهٔ خط (`ESC[K`)، همین پنل در هر Refresh بازنویسی می‌شود؛ بنابراین گزارش‌های جدید به انتهای ترمینال اضافه نمی‌شوند. دو خط باعث می‌شود اطلاعات اصلی پیشرفت از جزئیات مدل، کاشی‌ها، صف‌ها و VRAM جدا و خواناتر باشند.

نمونهٔ ظاهری (اعداد فرضی هستند):

```text
[=======---------------] 31.50% | 315/1,000 frames | Left 685 (68.50%) | 0.35 FPS | Elapsed 00:05:12 | ETA 00:32:41
Model=realesr-general-x4v3 | Tiles=4/12@192px b2 | Q=2/4,1/4 | D/P/E=8/2700/12ms/f | VRAM=5.42/8GB | RUNNING
```

اعداد صرفاً نمونه هستند. این دو خط در همان محل ترمینال بازنویسی می‌شوند و در هر Refresh یک پنل جدید به خروجی اضافه نمی‌شود.

- اگر FFprobe تعداد دقیق فریم‌ها را اعلام کند، همان مقدار استفاده می‌شود؛ در غیر این صورت تعداد تخمینی با علامت تقریبی نمایش داده می‌شود.
- FPS برای جلوگیری از نوسان زیاد هموارسازی می‌شود.
- ETA از تعداد فریم‌های باقی‌مانده و FPS هموارشده محاسبه می‌شود.
- اگر خروجی به فایل یا Pipe هدایت شود، برای هر به‌روزرسانی یک خط متن ساده نوشته می‌شود؛ بازنویسی یک خط در فایل Log کاربردی نیست.

گزینه‌های گزارش پیشرفت:

```text
--progress-interval SECONDS   فاصلهٔ زمانی به‌روزرسانی (پیش‌فرض: 1.0)
--no-progress                غیرفعال‌کردن گزارش پیشرفت
--no-color                   غیرفعال‌کردن رنگ‌های ANSI
```

## مرجع دستورات

نمایش تمام گزینه‌ها:

```bash
vidpipe --help
```

### ورودی و خروجی

```bash
vidpipe INPUT
vidpipe INPUT --output ./output/enhanced.mp4
vidpipe INPUT --output-dir ./output
vidpipe INPUT --config ./config.yaml
vidpipe INPUT --overwrite
```

- `INPUT`: فایل ویدئوی ورودی؛ FFmpeg معمولاً فرمت آن را خودکار تشخیص می‌دهد.
- `-o, --output`: مسیر دقیق فایل خروجی.
- `--output-dir`: پوشهٔ نام‌های خروجی خودکار.
- `--config`: فایل تنظیمات YAML.
- `--overwrite`: اجازهٔ جایگزینی فایل خروجی موجود.

### تنظیمات Encode

```bash
vidpipe INPUT --codec libx264 --crf 18 --preset slow
vidpipe INPUT --codec libx265 --crf 22 --preset medium
vidpipe INPUT --codec h264_nvenc --no-crf --video-option rc=vbr --video-option cq=19
vidpipe INPUT --pixel-format yuv420p --audio-codec aac --format mp4
```

| گزینه | کاربرد |
|---|---|
| `--codec` یا `--video-codec` | انکودر ویدئو در FFmpeg؛ مانند `libx264`، `libx265` یا `h264_nvenc` |
| `--crf N` | مقدار کیفیت برای انکودرهای پشتیبان CRF؛ محدودهٔ معتبر به انکودر بستگی دارد |
| `--no-crf` | ارسال نکردن گزینهٔ `-crf`؛ برای انکودرهایی که کنترل کیفیت دیگری دارند |
| `--preset NAME` | Preset سرعت/کیفیت؛ مقادیر معتبر به انکودر انتخاب‌شده وابسته‌اند |
| `--pixel-format FORMAT` | فرمت پیکسل خروجی؛ مانند `yuv420p`، `yuv444p` یا `p010le` |
| `--audio-codec NAME` | انکودر صدا یا `copy`؛ مقدار `none` صدا را حذف می‌کند |
| `--format NAME` | Container/Muxer خروجی؛ مانند `matroska`، `mp4` یا `webm` |
| `--video-option KEY=VALUE` | گزینهٔ اضافی انکودر ویدئو؛ برای چند گزینه می‌توان آن را تکرار کرد |

`CRF` برای همهٔ انکودرها قابل استفاده نیست. برای نمونه، NVENC معمولاً از گزینه‌هایی مانند `cq` یا `rc` استفاده می‌کند. گزینه‌های معتبر را با توجه به انکودر انتخاب‌شده در مستندات FFmpeg بررسی کن.

### تنظیمات Decode

```bash
vidpipe INPUT --input-format mov --decoder h264
```

| گزینه | کاربرد |
|---|---|
| `--input-format NAME` | اجبار FFmpeg به استفاده از Demuxer مشخص؛ حالت عادی تشخیص خودکار است |
| `--decoder NAME` | اجبار به استفاده از Decoder مشخص؛ حالت عادی انتخاب خودکار است |

### پردازش و حافظه

```bash
vidpipe INPUT --device gpu --tile-size 192 --tile-pad 16 --batch-size 2
vidpipe INPUT --device cpu --queue-depth 2 --no-half
```

| گزینه | کاربرد |
|---|---|
| `--device {auto,gpu,cpu}` | انتخاب دستگاه اجرای مدل |
| `--tile-size N` | عرض و ارتفاع کاشی برحسب پیکسل؛ حداقل ۶۴ |
| `--tile-pad N` | حاشیهٔ همسایگی اطراف هر کاشی |
| `--batch-size N` | تعداد کاشی‌های هم‌اندازه در هر فراخوانی مدل |
| `--queue-depth N` | حداکثر تعداد فریم نگهداری‌شده در هر صف Pipeline |
| `--half` | درخواست FP16 در صورت پشتیبانی مدل CUDA |
| `--no-half` | اجبار به اجرای مدل با FP32 |

Batch بزرگ‌تر ممکن است سرعت را افزایش دهد، اما VRAM بیشتری مصرف می‌کند. اگر خطای CUDA Out of Memory رخ دهد، مرحلهٔ مدل ابتدا Batch Size و سپس Tile Size را کاهش می‌دهد و فریم جاری را دوباره امتحان می‌کند.

### مشاهدهٔ قابلیت‌های FFmpeg

```bash
vidpipe --list-encoders
vidpipe --list-decoders
vidpipe --list-formats
vidpipe --list-pixel-formats
```

این دستورات انکودرها، دیکودرها، فرمت‌های ورودی و خروجی و Pixel Formatهای موجود در نسخهٔ FFmpeg نصب‌شده را نمایش می‌دهند.

## تنظیمات

فایل `config.yaml` شامل مراحل پردازش، دستگاه اجرا، محدودیت‌های حافظه، عمق صف‌ها و تنظیمات Encode در FFmpeg است. مراحل داخل `stages` به همان ترتیبی اجرا می‌شوند که در فایل نوشته شده‌اند.

نمونهٔ کلی یک مرحلهٔ مدل:

```yaml
stages:
  - name: model
    model: models/your-model.pth
    tile_size: 192
    tile_pad: 16
    batch_size: 1
    batch_size_max: 4
    half: true
```

برای انتخاب Tile Size، Padding و دقت محاسباتی، مستندات خود مدل را بررسی کن. همهٔ مدل‌ها از FP16 یا تمام اندازه‌های کاشی پشتیبانی نمی‌کنند.

## نام‌گذاری خروجی

اگر `--output` تعیین نشده باشد، `naming.py` نام فایل را از نام ورودی، نام مدل‌ها به ترتیب اجرا، ضریب Scale ترکیبی و برچسب Denoise (در صورت تشخیص از نام مدل) می‌سازد. اگر `--output` تعیین شود، همان مسیر دقیق استفاده می‌شود.

## اجرای تست‌ها

از ریشهٔ مخزن اجرا کن:

```bash
python -m pytest -q
```

تست‌ها اعتبارسنجی تنظیمات، وضعیت Controller، دریافت کلید بدون Enter، مدیریت حافظه، پردازش کاشی و بازیابی OOM، نام‌گذاری خروجی، Pipeline، گزارش پیشرفت و اطلاعات ویدئو را بررسی می‌کنند.

## کنترل‌های کیبورد

هنگام اجرای پردازش، کلیدها را بدون فشردن Enter بزنید:

| کلید | عملکرد |
|---|---|
| `P` | مکث موقت |
| `R` | ادامهٔ پردازش |
| `S` یا `Q` | توقف کنترل‌شده |
| `Ctrl+C` | درخواست توقف کنترل‌شده |

در لینوکس ورودی تک‌کلیدی با حالت cbreak ترمینال خوانده می‌شود؛ این حالت Echo را خاموش می‌کند اما سیگنال Ctrl+C را فعال نگه می‌دارد. تنظیمات اولیهٔ ترمینال پس از پایان کار بازیابی می‌شوند. اگر خروجی به فایل یا Pipe هدایت شده باشد، گزارش پیشرفت به‌صورت رکوردهای جداگانه نوشته می‌شود؛ بازنویسی یک خط فقط در ترمینال تعاملی امکان‌پذیر است.
